# Design System — shagoto.me

## 1. Design Identity

**Design direction:** Refined Technical Editorialism

The website should present Shagoto Sarkar as a serious computer science student, engineer, researcher, and thinker.

The visual language must feel:

* Formal
* Elegant
* Minimal
* Intellectual
* Contemporary
* Calm
* Precise
* Technically sophisticated
* Personal without being decorative

The site should feel like a **well-designed personal academic/engineering publication**, not a template portfolio, developer dashboard, hacker terminal, or cyberpunk experiment.

### Core principle

> **The sophistication should come from restraint, typography, spacing, hierarchy, and content—not visual effects.**

The visitor should notice the person and the work first, and the design system second.

---

# 2. Emotional Target

The first impression should communicate:

> "This person takes his work seriously, thinks deeply, and builds things carefully."

It should NOT communicate:

* "Hacker terminal"
* "Cybersecurity dashboard"
* "Gaming interface"
* "Cyberpunk"
* "AI-generated portfolio"
* "Startup landing page"
* "Developer template"
* "Loading screen"
* "Technology demo"

The website should feel closer to a **modern researcher's personal website, independent engineer's portfolio, or intellectual journal**.

---

# 3. Homepage Philosophy

The homepage is the most important page.

It must be the **quietest and most elegant part of the website**.

Do not attempt to demonstrate technical sophistication through visual gimmicks.

The homepage should use:

* Large, confident typography
* Generous whitespace
* Strong alignment
* Restrained borders
* Clear hierarchy
* Short sections
* Subtle metadata
* Carefully chosen typography
* Minimal motion
* High-quality composition

The homepage should be immediately understandable without requiring the visitor to decode a visual system.

### Above the fold

The hero should establish:

1. Who Shagoto is
2. What he does
3. What he is interested in
4. Where the visitor can explore further

The hero should not resemble a terminal.

Avoid:

```text
> initializing...
> system online
> user: shagoto
```

Avoid:

* Blinking cursors
* Fake command lines
* System status indicators
* Loading animations
* Matrix effects
* ASCII art
* Artificial "boot sequences"
* Fake logs
* Glitch effects

---

# 4. Visual Character

The visual language should combine:

### Editorial

Inspired by:

* Academic publications
* Modern magazines
* Research journals
* Personal essays
* High-end editorial websites

### Technical

Inspired by:

* Engineering documentation
* Research papers
* Technical diagrams
* Precise information architecture
* Well-designed developer documentation

### Personal

The website should still feel unmistakably like Shagoto rather than an institutional website.

The personality should emerge through:

* Writing
* Research interests
* Project choices
* Typography
* Content organization
* Small visual details

Not through excessive decoration.

---

# 5. Layout System

Use a strict but invisible grid.

The grid should create order without becoming visually obvious.

### Desktop

Use a centered content container with a comfortable maximum width.

Approximate content width:

```text
1100px – 1250px
```

Do not stretch text across the entire viewport.

Long-form text should remain at a readable measure.

### Mobile

The layout must remain intentionally designed rather than simply collapsing the desktop layout.

Prioritize:

* Comfortable margins
* Large enough typography
* Clear hierarchy
* Easy navigation
* No horizontal overflow
* No excessive UI density

---

# 6. Whitespace

Whitespace is a primary design element.

Do not fill empty space simply because it exists.

Use generous spacing:

* Between major sections
* Around headings
* Between content groups
* Around the hero
* Between navigation and page content

The site should feel **quiet and confident**.

A useful rule:

> If an element does not improve understanding, hierarchy, identity, or navigation, consider removing it.

---

# 7. Typography

Typography should carry much of the site's personality.

## Primary Editorial Typeface

Use:

**EB Garamond**

Purpose:

* Major headings
* Personal statements
* Research titles
* Long-form writing
* Editorial sections
* Important quotations

It provides an intellectual, literary, and human quality.

Do not use it for every UI element.

---

## Interface Typeface

Use a clean sans-serif for:

* Navigation
* Buttons
* Body UI
* Metadata where appropriate
* Forms
* Small interface text

Prefer a system or modern neutral sans-serif rather than introducing another highly distinctive display font.

The interface should remain quiet.

---

## Technical Typeface

Use:

**JetBrains Mono**

Only for:

* Code
* Technical metadata
* Tags
* Dates when appropriate
* Repository names
* Small technical labels
* Research identifiers
* Data-like information

Do not make the entire website monospace.

Monospace should function as an **accent language**, not the primary language.

---

# 8. Typography Hierarchy

Typography should have a strong hierarchy.

Example:

```text
EYEBROW / CATEGORY
Small, restrained, uppercase

Main Heading
Large editorial serif

Supporting description
Comfortable sans-serif or serif body text

Metadata
Small monospace / sans-serif

Body
Highly readable text
```

Avoid excessive font sizes.

Headings should feel substantial because of typography and whitespace, not because they are enormous.

---

# 9. Color System

Use a restrained monochromatic palette.

The default visual direction should be:

* Warm/off-white or very light neutral background
* Near-black primary text
* Muted gray secondary text
* Subtle gray borders
* One extremely restrained accent

The palette should feel sophisticated rather than technological.

### Important

Do not rely on:

* Neon cyan
* Neon green
* Electric blue
* Purple gradients
* RGB effects
* Glowing borders
* Cyberpunk color combinations

Technical identity must not become "hacker aesthetic."

---

# 10. Dark Mode

If dark mode is implemented, it should be an **editorial dark theme**, not a hacker theme.

Use:

* Near-black / charcoal background
* Soft off-white text
* Muted secondary text
* Very subtle borders
* Restrained accent

Avoid:

* Pure black + neon green
* Glowing text
* Scanlines
* CRT effects
* Terminal styling
* Excessive contrast everywhere

Dark mode should feel like a **quiet reading environment**.

---

# 11. Borders and Surfaces

Prefer borders over shadows.

Use:

* Thin rules
* Hairline dividers
* Subtle section boundaries
* Simple cards where genuinely useful

Avoid:

* Heavy drop shadows
* Glassmorphism
* Floating translucent cards
* Excessive panels
* Decorative containers

Cards should not become the default container for every piece of information.

Whenever possible, let typography and spacing define structure.

---

# 12. Navigation

Navigation should be extremely simple.

Possible structure:

```text
Shagoto Sarkar

Research   Projects   Notes   CV   Contact
```

The navigation should:

* Remain visually quiet
* Have excellent spacing
* Clearly indicate the current page
* Work perfectly on mobile
* Avoid oversized UI
* Avoid hamburger-menu theatrics unless necessary

Do not create dashboard-style navigation.

---

# 13. Homepage Structure

The homepage should follow a simple hierarchy.

### 01 — Identity

Introduce Shagoto clearly.

Example conceptual structure:

```text
Shagoto Sarkar

Computer Science · Engineering · Research

A short statement describing what he builds,
what he studies, and what questions interest him.
```

Do not write generic statements such as:

> "Passionate developer who loves turning ideas into reality."

The writing should be specific and intellectually credible.

---

### 02 — Selected Work

Show a small number of meaningful projects.

Prioritize quality over quantity.

Each project should communicate:

* What it is
* Why it exists
* What Shagoto actually did
* Technologies when relevant
* Current status
* Link to deeper project page

The homepage should not contain the entire project archive.

---

### 03 — Research

Research should be visible as a major part of the identity.

Show:

* Current research direction
* Selected research work
* Research questions
* Publications/preprints when they genuinely exist
* Related technical investigations

Do not fabricate publications, results, affiliations, or achievements.

---

### 04 — Thinking / Notes

A small selection of notes can demonstrate intellectual range.

Possible themes include:

* Computer science
* Engineering
* AI
* Neurosymbolic systems
* Linux
* Systems
* Books
* Ideas

The section should feel like an intellectual notebook rather than a content-marketing blog.

---

### 05 — Current Focus

A small, restrained section can communicate what Shagoto is currently working on.

This should be informational, not a fake "live system status."

Good:

```text
Currently exploring

Reliable neurosymbolic reasoning
Iterative information acquisition
Symbolic verification
```

Bad:

```text
● SYSTEM ACTIVE
PROCESS: NEUROSYMBOLIC_AI
CPU: 42%
STATUS: ONLINE
```

---

### 06 — Closing

End with a simple invitation to explore the work or get in touch.

No giant marketing CTA.

---

# 14. Project Pages

Project pages may become more technical than the homepage.

This is where the engineering identity can become more visible.

A project page should prioritize:

1. Problem
2. Context
3. Approach
4. Architecture
5. Implementation
6. Decisions
7. Results
8. Limitations
9. Future work
10. Repository/demo

Technical diagrams, code snippets, architecture diagrams, tables, and monospace metadata are appropriate here.

However, even project pages should remain visually disciplined.

---

# 15. Research Pages

Research pages should feel scholarly.

Prioritize:

* Research question
* Motivation
* Background
* Hypothesis
* Method
* Experimental design
* Findings
* Limitations
* References
* Current status

Use typography and whitespace inspired by academic reading.

Avoid pretending unfinished research is a completed publication.

Clearly distinguish:

```text
Idea
In progress
Experiment
Preprint
Published
```

---

# 16. Notes

Notes should feel editorial and readable.

Long-form writing should prioritize:

* Reading width
* Line height
* Paragraph rhythm
* Headings
* Citations/references where appropriate

Do not overload notes with UI.

The reader should forget that they are browsing a portfolio and simply read.

---

# 17. Technical Aesthetic

Technical details should exist as **subtle texture** throughout the website.

Examples:

```text
2026
RESEARCH
NEUROSYMBOLIC AI
```

or:

```text
PROJECT / DIU2EVERYWHERE
STATUS / IN DEVELOPMENT
STACK / PHP · MySQL · Flutter
```

These elements should support information architecture rather than become decoration.

The technical layer should be discovered gradually.

---

# 18. Motion

Motion should be minimal.

Prefer:

* Subtle opacity changes
* Small positional changes
* Gentle page transitions where useful

Avoid:

* Loading animations
* Glitch effects
* Cursor animations
* Parallax everywhere
* Text scrambling
* Typing animations
* Infinite animations
* Decorative particle systems

### Principle

> Motion should explain a change, not prove that the website can animate.

Respect `prefers-reduced-motion`.

---

# 19. Images

Images should be used only when they add information or personality.

Prefer:

* Project screenshots
* Architecture diagrams
* Research figures
* Carefully selected photographs
* Relevant visual documentation

Avoid:

* Generic stock photos
* AI-generated tech imagery
* Random laptop photographs
* Decorative 3D renders
* Abstract technology backgrounds

---

# 20. Icons

Icons should be restrained.

Use icons only when they improve recognition or navigation.

Do not create an icon for every label.

Avoid oversized social-media icon clusters.

Text links are often preferable.

---

# 21. Components

Components should be simple and reusable.

Prefer:

* `Header`
* `Footer`
* `ProjectCard`
* `ResearchCard`
* `NoteCard`
* `SectionHeading`
* `Metadata`
* `Tag`
* `Pagination`

Avoid building a large component library before there is a genuine need.

---

# 22. Cards

Cards are not the visual foundation of the website.

Use them selectively.

A project card should feel closer to an editorial index entry than a SaaS dashboard card.

Prefer:

```text
PROJECT
DIU2EVERYWHERE

A real-world ride-sharing platform
for the DIU community.

PHP · MySQL · Stored Procedures

→ Explore project
```

over:

```text
╭────────────────────────────╮
│ 🚀 DIU2EVERYWHERE          │
│                            │
│ ⭐ Featured                │
│ 🟢 Active                  │
│                            │
│ [PHP] [MySQL] [Flutter]    │
│                            │
│        VIEW PROJECT →      │
╰────────────────────────────╯
```

---

# 23. Accessibility

Accessibility is part of the design system.

Ensure:

* Strong text contrast
* Keyboard navigation
* Visible focus states
* Semantic HTML
* Correct heading hierarchy
* Accessible links
* Accessible forms
* Reduced-motion support
* Mobile readability

Do not sacrifice accessibility for visual minimalism.

---

# 24. Responsive Design

The site should feel intentionally designed at:

* Large desktop
* Laptop
* Tablet
* Mobile

Do not simply shrink desktop components.

On smaller screens:

* Reduce horizontal complexity
* Preserve typography hierarchy
* Maintain generous vertical rhythm
* Simplify navigation
* Avoid tiny metadata
* Preserve readable line lengths

---

# 25. Performance

The aesthetic should never depend on heavy JavaScript.

Prefer:

* Static HTML
* CSS
* Optimized assets
* Build-time rendering
* Minimal client-side JavaScript

JavaScript should be introduced when it provides meaningful functionality.

Do not impose "zero JavaScript" as an ideology if a small amount of JavaScript materially improves accessibility or usability.

---

# 26. Content Authenticity

The visual design must never encourage fabricated content.

Never invent:

* Publications
* Awards
* Companies
* Employment
* Research results
* Metrics
* Testimonials
* Certifications
* Professional claims

If information is missing, design around the absence rather than filling it with invented material.

A simple:

```text
Research in progress
```

is better than fabricated evidence.

---

# 27. Design Anti-Patterns

The following are explicitly prohibited unless there is a compelling functional reason:

### Hacker aesthetic

* Terminal homepage
* Fake command prompts
* Blinking cursor
* System logs
* "Initializing..."
* "System online"
* Matrix rain
* CRT effects

### Cyberpunk aesthetic

* Neon gradients
* Glowing text
* RGB borders
* Excessive cyan/green/purple
* Glitch effects

### Generic portfolio aesthetic

* Giant "Hi, I'm a passionate developer!"
* Skill bars
* Percentage-based skill ratings
* Excessive technology logos
* Generic testimonial sections
* Stock developer illustrations
* "10+ technologies mastered" claims

### SaaS aesthetic

* Excessive rounded cards
* Huge gradient hero
* Floating glass panels
* Excessive shadows
* Marketing-style CTA sections

---

# 28. Design Hierarchy by Section

Different sections may reveal different aspects of the identity.

| Area     | Primary Character        |
| -------- | ------------------------ |
| Homepage | Elegant / Editorial      |
| Research | Scholarly / Intellectual |
| Projects | Technical / Engineering  |
| Notes    | Literary / Editorial     |
| CV       | Formal / Professional    |
| Contact  | Minimal / Personal       |

The website should therefore **not look identical on every page**.

The underlying design system remains consistent, while the content context determines how strongly each visual language appears.

---

# 29. Design Principle

The entire website should follow this hierarchy:

```text
CONTENT
  ↓
TYPOGRAPHY
  ↓
LAYOUT
  ↓
SPACING
  ↓
COLOR
  ↓
DETAIL
  ↓
MOTION
```

Never reverse this hierarchy.

Do not begin with effects and then search for content to put inside them.

---

# 30. Final Creative Direction

If the design needs a single sentence of direction, use:

> **A refined personal digital publication for a computer scientist—editorial, minimal, intellectual, and quietly technical.**

The site should feel **expensive because it is restrained**, not because it is visually extravagant.

It should be memorable because of its **clarity, typography, content, and personality**.

The goal is not to make visitors think:

> "Wow, this website has lots of effects."

The goal is to make them think:

> **"There is a serious mind behind this."**
